AI project · retrieval-augmented generation

yakov.LLM

A portfolio is a stack of repositories that nobody has time to read. So I built a reader that never gets tired: an AI assistant that has gone through every line I have pushed to GitHub, answers questions about it in Hebrew or English, and points to the exact lines behind each answer. And when I push a change, it reads that too.

the idea

The problem

A recruiter opens my GitHub for a minute and a half. In that time they can't learn why the Bomberman enemy uses breadth-first search, how FitVision counts a squat, or why The Map Lies never forces a guess. All of that is in the code, but nobody will dig for it.

The answer

  • Ask anything about my projects, in Hebrew or English
  • Every claim in the answer carries a number like [2]
  • Click it, and the exact lines open with a link to them on GitHub
  • If the code doesn't say, it says so. No made-up features
  • Attach a job description, a CV or a whole folder, and it connects them to the projects
  • Feels like a real chat app: it answers in your language, remembers you, and lets you pin, rename, search and edit

from question to cited answer

Read

Follow my GitHub account and pull every repo: code, docs, pages and config.

Split

Cut files into passages that remember their repo, path and line numbers.

Search

Rank the passages for the question with a BM25 engine I wrote from scratch.

Write

A language model drafts the answer from the top passages only, streamed word by word.

Cite

Each claim links to its passage, so the reader can check the source instead of trusting the model.

a search engine from scratch

I could have used a vector database and an embedding model. For about 7,000 passages full of exact identifiers like find_path_step or RBAC, plain keyword ranking is faster, needs no model download, and is easy to explain. The interesting part was making it understand both of my languages:

Code-awarefindPathStep also counts as find, path and step, and chase_range as chase and range.
Hebrew-awareHebrew glues words together: “והאויבים” also searches for “האויבים” and “אויבים”.
BilingualA Hebrew question about English code gets English search terms: “אויב” brings in enemy, “רודף” brings in chase.
Fair rankingWords in file names and headings weigh more, test files step back unless you ask about tests, and no single file can fill the whole answer.
# BM25: rare words that appear often in a short passage score highest
score += idf(term) * tf * (K1 + 1) / (tf + K1 * (1 - B + B * length / avg_length))

it reads the code, not just the words

People don't ask in the code's words. They ask "who calls this?", "what does it depend on?", "how do I run it?". So on every push yakov.LLM reads the code itself and writes a fact card for everything in it. Nothing is written by hand, so nothing goes stale.

Every function and classIts signature, docstring, file and lines, what it calls and where it is used. Python is parsed with ast; JavaScript, TypeScript and Java with careful patterns.
Every fileIts role, what it defines and what it imports.
Every projectDependencies, run commands, tests and CI, API endpoints, database tables, settings and folder structure.
Tested at scale750 auto-generated questions about random functions and files, in Hebrew and English. 93% reach the right file; the misses are names like __init__ that are ambiguous by nature.

it remembers, carefully

Talk to it today and come back next week, and it remembers what you asked about. What visitors tell it is a different matter: a claim from a stranger is not a fact about my code.

Separate from knowledgeThe knowledge base is built only from the repos. What people say goes to a separate store, marked unverified, for me to read.
A name proves nothingOn the same device it recalls the whole conversation. Someone on another device who uses the same name only hears that a person by that name talked before, never what was said.

it keeps itself up to date

A portfolio assistant that forgets my latest work is worse than none. yakov.LLM compares every repo's last push time with what it already knows, and re-reads only what changed. There are three ways it hears about a change:

Every 30 minutesThe server checks my GitHub account and swaps in the new index without a restart.
On every pushA webhook with a signed secret can trigger a sync within seconds.
Every 6 hoursA GitHub Action rebuilds the knowledge base and republishes the app.
The first surpriseOn its very first run, it found a new project on my account and read its code. The project was yakov.LLM itself.

automated tests, plus guards that fail CI if accuracy drops
  • The same search engine runs in Python on the server and in JavaScript in the browser. A test runs both on every question and requires identical results.
  • The server has no dependencies: the HTTP server, the streaming model client and the search engine all use only the standard library.
  • The model is pluggable: Gemini and Groq on free tiers, Claude, or any OpenAI-compatible API. Without any key it still answers with the matching passages.

key insights

Retrieval is the product

The model can only be as right as the passages it gets. Measuring the search did more for answer quality than any prompt tweak.

Citations build trust

An answer you can check in one click is worth more than a longer one you have to believe.

Simple beats fashionable

BM25 plus a small bilingual glossary beat my expectations for code questions. The evaluation set will say when embeddings start to pay off.

Build with AI, verify like an engineer

I built yakov.LLM with Claude as a pair programmer. The tests, the evaluation set and the parity check are how I made sure that what we built actually works.
