architecture

The key design decision: the game logic never imports Pygame. That is what lets every rule be tested without opening a window.

two algorithms that make it smart

The enemy hunts you with BFS

Breadth-first search finds the first step on the shortest path to the player, around walls and bombs.

queue = deque([(start, None)])
while queue:
    pos, first = queue.popleft()
    for d in Direction:
        nxt = step(pos, d)
        if nxt == goal: return first or d
        if walkable(nxt) and nxt not in seen:
            seen.add(nxt)
            queue.append((nxt, first or d))

Chain reactions with a queue

Every bomb a flame touches joins the queue, and each bomb explodes exactly once.

queue = list(due_bombs)
while queue:
    bomb = queue.pop()
    if bomb in done: continue
    done.append(bomb)
    for tile in flame_path(bomb):
        other = bomb_at(tile)
        if other and other not in done:
            queue.append(other)

key insights

Separate logic from display

Keeping Pygame out of the rules made the core testable, and turned the renderer into a thin layer that is easy to change.

Tests alongside the code

Writing tests in parallel with each module, not at the end, kept the last weeks free for user testing and polish.

Data over hard-coding

Levels are plain text files and constants live in one place, so the game can grow without touching the engine.

Engineering is more than code

A spec, a plan with roles and a presentation are what make a team project deliverable on time.
